## Как это устроено
- Мод — это папка верхнего уровня с собственным Gradle-проектом (`build.gradle`, `settings.gradle`, `gradlew`,
  `gradle.properties` с `mod_id`) и своим README.
- GitHub Actions (`.github/workflows/build.yml`) находит такие папки сам и собирает **только те моды, чьи папки
  изменились** в пуше (все — при ручном запуске или изменении workflow).
- Каждая сборка проходит smoke-тест на headless-сервере: любая ошибка загрузки данных мода валит сборку. Свои
  дополнительные проверки мод может положить в `tools/ci/smoke_check.sh`.
- Пуш в `main` публикует релиз мода с тегом `<папка>-v<версия>-build.<номер>`; jar прикреплён к релизу.
- Логи сборок — в ветках `ci-logs-<папка>`.

## Новый мод
Создать папку рядом с `retrocosmos/` (например `mymod/`) с Gradle-проектом NeoForge 1.21.11 и `mod_id` в
`gradle.properties` — следующий пуш соберёт его и выпустит отдельным релизом.
